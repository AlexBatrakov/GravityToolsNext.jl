Observation sources and selection

These operations prepare observations entirely in Julia. Epochs have not been aligned to a timing model. They perform no engine execution, noise draw, fitting or hidden file write. ObservationSource owns a document, ordered lineage and saved settings; write its document explicitly with write_tim_document.

using GravityToolsNext, Random

source = tim_source("observations.tim"; precision_bits=128)
selected = select_toas(source; method=:random, count=32, rng=Xoshiro(42))
write_tim_document(selected.document, "selected.tim")
mapping = selected.lineage # retain separately when persisting the output

schedule = regular_schedule("55825.123456789012345678901234";
    count=12, cadence_s=600, observatory="pks",
    frequency_mhz=1400, uncertainty_us=2, backend="PDFB1")

explicit_schedule(epochs; ...) retains supplied order and duplicates. regular_schedule(start_mjd; count, cadence_s, ...) uses exactly count > 0 epochs, each computed from the anchor as start+(i-1)*cadence_s/86400, with positive finite cadence in site seconds. Both use explicit >=128-bit precision. Absolute MJDs accept S1 decimal strings, BigFloats with >=128 bits, or exact integer days; Float64 absolute MJDs are rejected. Regular cadence can be Float64 seconds. Generation preserves the binary epoch through enough decimal digits to round-trip it at document precision. It does not invent -pn or validate the physical effects of explicitly supplied flags.

Site/frequency/nominal uncertainty, backend and filenames accept shared scalars or vectors matching the epoch count. flags accepts an ordered shared pair vector or one pair vector per observation; duplicates are retained. Backend adds one -be pair; combining backend with an explicit -be is rejected. Alternatively, pass a backend sequence and a simple system dictionary:

systems = Dict(
    "A" => (observatory="pks", frequency_mhz=1400, uncertainty_us=2,
            flags=["-fe"=>"receiver1"]),
    "B" => (observatory="@", frequency_mhz=0, uncertainty_us=3),
)
schedule = explicit_schedule(["55825.0", "55825.1", "55825.1"];
    backend=["A", "B", "A"], systems=systems)

systems replaces direct site/frequency/uncertainty arguments; mixing them is an error. Unknown/missing systems fail. Additional supplied flags follow system flags, then the backend pair. Unused system definitions are permitted and saved. Resolved per-observation metadata, exact decimal epochs and schedule parameters remain in settings. No cadence-distribution or scheduling language is implied. Generated filenames beginning C, I or # are rejected explicitly so no requested observation can turn into a comment or inactive row.

All selection methods retain input order, not chronological order. There is no replacement or duplicate-ID selection; identical observations remain distinct.

MethodCount and order policy
:allEvery TOA, unchanged order
:randomExactly count or floor(N*fraction), using randperm then restoring input order
:stratifiedExactly a total count/fraction, proportional largest-remainder group allocation; ties use lexical group labels. Alternatively a complete group_counts dictionary names every observed group, including zero-count groups
:strideoffset:stride:N, default offset=1; positive stride and offset within input bounds
:time_windowInclusive time_start/time_finish MJD, at least one bound; current edited epochs are used

Counts must be positive and not exceed capacity. Fractions lie in (0,1]; a floored zero result fails rather than being rounded up. Fraction multiplication uses its numeric type; BigFloat products use explicit sufficient precision, independent of ambient settings. Use an exact rational for boundary-sensitive count fractions. No implicit count is supplied to random methods. Time bounds accept decimal strings, >=128-bit BigFloat or integer days, not Float64. Empty results, reversed windows and method-inapplicable keywords fail clearly.

Stratification defaults to group_flag="-be". Every TOA must have exactly one such flag: missing or repeated flags, even equal repeated values, are errors. Unknown, omitted, negative, noninteger or over-capacity explicit group counts are errors; their total must be positive. Groups are processed in lexical order. Selection retains all supported header/comment/blank nodes in original relative order, including comments adjacent to removed TOAs; those comments are treated as document text, not automatically reassigned observation annotations.

Random methods require exactly one explicit rng or nonnegative integer seed. Seed convenience creates a private Xoshiro. Supplied RNGs are consumed; repeating a request from the same initial RNG state reproduces it. Reusing a consumed RNG does not promise repetition. Settings retain RNG type, initial state copy, seed when supplied, Julia version, allocation, selected input indices and counts. Algorithms use randperm; results are not promised identical across Julia/RNG versions. Nonrandom selection and schedules consume no RNG. Keep other random processes on independent streams. Selection is not train/test splitting.

subset_tim_document(doc, ids) is the supported low-level composition API; it copies in input order and preserves current epochs, raw lines, original ordinals/IDs and source-file protection. create_tim_document(rows) constructs generated observations without inventing original paths or inodes. Generated documents have origin == :generated and source_path, source_realpath, source_file_id equal to nothing. Their content hash and TOA IDs belong to the generated namespace. File reads use :file; the original two-argument TimTOAID(hash, line) constructor still means file origin.

Lineage gives output index, original source ID and original source ordinal, including through successive selections. A changed output read from disk has new file IDs; keep the returned mapping separately. Documents/snapshots/settings are independently owned. Mutate epochs via the accepted TIM editing API.

See examples/observation_sources.jl for an example with explicit output paths. Existing file-origin sources and genuine explicit/regular schedules can feed the bounded noiseless template API. Generated inputs retain their origin and selected IDs through phase bootstrap and strict final MODE 1 verification; source construction alone makes no timing-model claim.

GravityToolsNext.ObservationSource — Type
ObservationSource

Owned document::TimDocument, ordered lineage::Vector{TOALineage}, and saved settings::NamedTuple. Construct via tim_source, explicit_schedule, or regular_schedule; select with select_toas. None of these operations writes files or evaluates a timing model. Persist lineage separately from a written TIM.

GravityToolsNext.explicit_schedule — Function
explicit_schedule(epochs; observatory, frequency_mhz, uncertainty_us,
                  backend=nothing, flags=[], filenames=nothing,
                  systems=nothing, precision_bits=128, mode=nothing)

Create a deterministic generated-origin source in supplied epoch order, retaining duplicates. Epochs are plain decimal strings, >=128-bit BigFloat or exact integer days. Metadata accepts scalars or vectors of exactly matching length. flags is a shared ordered pair vector or one pair vector per TOA. Optional systems maps backend strings to named tuples containing site/frequency/uncertainty and optional flags; it replaces direct site/frequency/uncertainty inputs. A supplied backend adds one -be pair and must not overlap explicit -be flags. No RNG, hidden write, pulse numbering or model evaluation is used. Saved settings contain resolved per-observation metadata and decimal epoch strings.

GravityToolsNext.regular_schedule — Function
regular_schedule(start_mjd; count, cadence_s, precision_bits=128, kwargs...)

Generate exactly count > 0 observations at start + (i-1)*cadence_s/86400. Cadence is positive finite site seconds; absolute MJD never passes through Float64. Compute each epoch from the anchor at explicit precision, avoiding accumulated cadence rounding. Other metadata keywords match explicit_schedule. This constructs a schedule, not timing-model-aligned or noiseless arrivals.

GravityToolsNext.select_toas — Function
select_toas(source; method=:all, count=nothing, fraction=nothing,
            rng=nothing, seed=nothing, stride=1, offset=1,
            time_start=nothing, time_finish=nothing,
            group_flag="-be", group_counts=nothing)

Select a nonempty independent source in input order, without replacement. Methods: :all; :random (exact count or floor(N*fraction)); :stratified (proportional largest-remainder counts with lexical group ties, or explicit complete groupcounts); :stride (offset:stride:N); `:timewindow` (inclusive MJD bounds, at least one bound). Do not combine method-specific settings.

Random methods require exactly one explicit AbstractRNG or nonnegative integer seed (private Xoshiro). Supplied RNGs are consumed; settings save a copy of the initial state, type, seed if provided and Julia version. Replay starts from the same state, not a reused consumed RNG. No default/global RNG is used. Stratified TOAs require exactly one grouping flag, even if repeated values agree. Explicit group counts must name every observed group, allow zero per group, fit capacities and have positive total. Non-random methods consume no RNG.

All supported raw document lines are retained. Original IDs/current epochs and lineage persist; writing and re-reading gives new file IDs, so persist the mapping separately. Selection is not a temporal train/test split or model idealization.

GravityToolsNext.subset_tim_document — Function
subset_tim_document(document, ids) -> TimDocument

Copy selected TOAs in original document order, retaining every supported raw comment/header/blank node in its original relative position. Reject repeated or foreign IDs. Preserve current edited epochs, original IDs/ordinals, precision, origin and source-file overwrite protection. Empty subsets are representable. The returned document is independent of the input. This does not rebase pulses.

GravityToolsNext.create_tim_document — Function
create_tim_document(observations; precision_bits=128, mode=nothing)

Construct a generated-origin FORMAT 1 document without files or hidden writes. Each observation supplies epoch_mjd, observatory, frequency_mhz, and uncertainty_us; optional filename defaults to obs_000001, etc., and flags is an ordered vector of pairs. Epochs accept plain decimal strings, >=128-bit BigFloat or exact integer days, never Float64. Validate the S1 subset. Generated IDs hash the constructed bytes in the :generated namespace; source paths and inodes are nothing. No pulse numbers or phase connection are invented.
